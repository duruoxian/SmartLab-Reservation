## 一、主推项目：智约·校园实验室设备预约管理系统

### 1. 项目一句话介绍

面向学生、教师和实验室管理员，提供实验室设备浏览、预约申请、审批、签到/归还、违约记录、统计报表和后台管理的桌面端系统。

### 2. 为什么适合你们？

- 技术栈完全匹配：C++/Qt/QML 做客户端，Python 做后端，数据库用 SQLite/MySQL。
- 功能边界清晰，3 人 10～12 周能做完。
- 有用户端 + 管理端，文档里的“工作内容、产品、服务、非移交产品”都好写。
- 有审批、状态流转、统计，方便写项目管理和测试用例。
- 演示效果好：登录、预约、审批、统计图表都能现场展示。
- 比二手交易、社交、AI 项目稳很多，不容易烂尾。

### 3. 建议功能范围

**用户端：**

- 注册登录、个人中心
- 设备列表、分类、搜索、详情
- 预约申请、取消预约
- 我的预约、签到/归还
- 消息通知

**管理端：**

- 设备管理、实验室管理
- 预约审批、违约处理
- 用户管理、权限管理
- 统计报表：使用率、预约量、违约率
- 操作日志

**不要做：**

- 实时聊天、支付、地图定位
- 复杂推荐算法、人脸识别
- 多级复杂审批流
- 真实硬件控制

### 4. 技术栈建议

- 客户端：C++17、Qt 6、QML、Qt Quick Controls 2、Qt Network、Qt Charts
- 后端：Python FastAPI 或 Flask
- 数据库：SQLite 开发，MySQL 部署
- 通信：HTTP + JSON RESTful API
- 工具：CMake、Git、Postman/Apifox、Figma/Axure
- 可选：Docker、云服务器，学生项目可不用

### 5. 3 人分工

| --- | ------------------- | ----------------------------------- |

| B   | Python 后端 + 数据库     | API 设计、数据库、权限、审批逻辑、统计接口、部署          |
| C   | 测试 + 文档 + UI + 进度   | 原型、测试计划、用例、黑盒/接口测试、文档、PPT、进度跟踪      |
| 全体  | 编码/联调/答辩            | 增量开发、集成测试、展示准备                      |

### 6. 增量与里程碑建议

| 阶段        | 内容                 | 里程碑        |
| --------- | ------------------ | ---------- |
| 第 1～2 周   | 需求调研、项目管理概述、WBS、原型 | M1 需求与原型完成 |
| 第 3～4 周   | 数据库设计、API 设计、UI 设计 | M2 设计完成    |
| 第 5～7 周   | 增量1：登录、设备浏览、预约申请   | M3 客户端核心完成 |
| 第 8～9 周   | 增量2：审批、签到/归还、通知    | M4 业务闭环完成  |
| 第 10～11 周 | 增量3：后台管理、统计报表、测试   | M5 系统测试完成  |
| 第 12 周    | 总结报告、PPT、答辩、验收     | M6 交付验收    |

### 7. 项目管理概述里可以这样写

- **背景**：校园实验室设备人工预约效率低、冲突多、记录难追踪。
- **产品**：Qt/QML 桌面客户端 + Python 后端 + 数据库。
- **文件**：项目开发计划、需求分析、概要设计、详细设计、测试计划、源文件。
- **服务**：培训安装、维护、运行支持。
- **预算**：打印文档、可选云服务器，学生项目基本 0～200 元。
- **最迟期限**：按你们课程时间填，比如 20XX 年 X 月底。

## 1 引言

### 1.1 编写目的

### 1.2 背景

智约·软件工程实验室设备预约管理系统供软件工程实验室的学生、教师和管理员使用。师生可查询设备、申请和取消预约、签到与归还。管理员处理审批、设备台账、用户权限、违约和统计。开发小组为第9组，指导教师为彭顺顺。

规划业务边界遵循《需求说明书》：学生、教师及管理员作为本人预约申请人时，按相同的预约、取消、签到和归还规则处理；管理员另承担审批与管理职责，不得把管理权限用于绕过本人预约校验。设备逾期未归还时登记违约并暂停设备新预约，待管理员确认实物归还后再恢复接单条件；维护或停用状态继续独立生效。这些预约、交接和违约规则均属后续规划，当前 M01 尚未实现任何角色的预约业务。

### 2.3 通用接口和开发顺序

当前共11个业务接口，另有 GET /api/health 健康检查，统一使用 /api 前缀，JSON 为 {code, message, data}；成功均为 HTTP 200，code=200。请求校验错误转换为 HTTP 400而非默认422。错误包括401未认证、403越权或账号受限、404不存在、405方法不支持、409业务冲突、423登录锁定、500内部错误；健康检查在数据库不可用时返回503。当前管理员用户分页返回 items、page、has_more，不返回 total 或 list。其余业务分页拟返回 items、total、page、page_size，须在对应模块实现时确定。

当前默认 API 为 http://127.0.0.1:8765，SQLite 文件为 backend/data/smartlab.sqlite3，连接可由 SMARTLAB_DB_URL 指定；部署 MySQL 还需配置签名密钥。现有 M01 的创建、锁定、冻结、审计及最近活动时间使用 Unix 秒。规划预约等业务按实验室时区判断日期窗口，数据库存 UTC DATETIME(3)。常规业务目标不超过2秒；完整负载验收按50在线用户、1000台设备、2000用户和5万条预约记录规划。

实施基线是现有 M01：注册、登录、资料维护、密码修改、恢复码更新与重置、退出、管理员用户查询及角色调整。后续顺序为设备查询 → 预约 → 审批与签到归还 → 消息 → 台账与完整账号启停 → 统计 → 审计与违约联调。违约、预约联动、消息轮询及统计尚须实现和系统验证。

后续系统验收按需求编号记录结果，形成注册登录、设备查询、预约申请、审批、签到归还和通知闭环，并复验并发冲突、权限隔离、统计与备份恢复。覆盖全部高优先级及至少80%的中优先级需求、黑盒通过率95%为完整系统验收目标。本说明书不以源码存在或 SQL 定义替代测试记录。

### 2.4 实现边界与设计约定

当前四个 ORM 实体为 t_user、t_dict、t_auth_session、t_operation_log。backend/sql/smartlab_schema_mysql80.sql 定义16张 t_ 前缀表，除上述4表外，还包括 t_dept、t_lab、t_lab_open_hour、t_equipment、t_reservation、t_res_slot、t_equipment_custody、t_approval_log、t_violation、t_password_reset、t_notification_event、t_notification。业务状态使用字符串和 CHECK 约束，不采用数字 ENUM；不同实体按停用、归档、软删除或清理分别处理，不统一增加 is_deleted。

当前 M01 使用24位一次性恢复码，摘要保存在 t_user.recovery_hash；管理员签发凭证及 t_password_reset 为预留方案。当前没有独立 refresh 接口、refresh_token 或8小时绝对会话上限。教师工号外部核验、实验室工作日配置及角色调整时的未完成预约处置属于后续业务设计。M03 自助取消按距开始至少2小时处理；逾期设备的后续预约由管理员协调，保留历史记录。

现有 SQLite ORM 建表仅覆盖 M01 四表，不能直接执行 MySQL 方言脚本初始化 SQLite。完整业务需扩展模型，再在 SQLite 与 MySQL 8.0.16及以上环境分别验证事务、并发、迁移和恢复；SQL脚本的存在不表示16表业务已实现。本说明书引用完整数据库设计中的字段与约束，不在此重复全部 DDL。既有 UML 不作修改，其中数据库图字段尚待与新版16表设计同步，结构约束以新版 SQL 和数据库说明为准。

## 3 登录模块设计说明

### 3.1 登录模块

当前 M01 覆盖 FR-101-2、FR-102-2 和 NFR-S6。AuthPage.qml 提供登录，UserViewModel 管理 busy、message、user 等状态，ApiClient 发送请求并保存令牌。Main.qml 按当前角色显示入口；师生首页的设备区仍为占位，管理员可进入 RolePage.qml。F01～F10 是完整业务的页面标识映射，不等于现有同名 QML 文件。

当前 UserService 负责账号状态、连续失败计数、会话与审计；UserRepository 和四个 ORM 实体负责持久化。UserViewModel 是共享 QObject，ApiClient 是其普通 C++ 类值成员，不是单例或 QObject，也不提供 QObject 信号接口；经 Qt Network 发送请求，单次传输超时8秒，无自动重试。当前五个 QML 单元为 Main、AuthPage、ProfilePage、RolePage 和 FormField。其他业务 ViewModel 与调度器均属规划。

### 3.2 性能

正常登录接口响应目标不超过1.5秒，含密码散列验证、会话落库与签发。当前用户查询设计目标不超过1秒。

连续输错5次锁定10分钟，lock_until 保存 Unix 秒。JWT 有效期1800秒，并以 t_auth_session.last_activity_at 校验30分钟空闲失效；活动时滚动续签。登录失败计数提交后再返回错误，避免异常回滚丢失计数。并发、耗时及边界应按测试用例验收。

### 3.3 输入项

| 输入项 | 来源或格式 | 当前约束及校验 |
| --- | --- | --- |
| user_no | AuthPage，字符串 | 8～12位字母数字，去首尾空白并转小写，保留前导零。 |
| password | 登录请求 | 1～128字符，原样验证；日志不记录口令。新设密码规则见第4章。 |

### 3.4 输出项

| 输出项 | 当前内容 | 使用方 |
| --- | --- | --- |
| 登录成功 | data={token,user}；JWT载荷 user_id、role、sid、iat、exp。 | 客户端缓存本次令牌和用户。 |
| 失败 | 前4次错误401，第5次和锁定中423；禁用403；423 data含 lock_until、retry_after。 | 界面显示通用凭据或锁定提示。 |
| 当前用户 | id、user_no、name、role、college、major、phone、status、violation_count、frozen_until、booking_frozen。 | 本人资料与权限状态展示。 |
| 滚动令牌 | 受保护响应头 X-SmartLab-Token；不是 refresh_token。 | ApiClient 替换旧令牌。 |

### 3.5 算法

按规范化的 user_no 查询 t_user，账号状态仅为“启用/禁用”，临时锁定由 fail_count 和 lock_until 表达。禁用返回403；锁定中返回423及 lock_until、retry_after。密码前4次错误返回401，第5次写锁定截止并返回423；到期清空旧轮计数。密码采用 PBKDF2-HMAC-SHA256、100000次迭代：16字节随机盐转32字符十六进制，以该盐文本的 ASCII 字节参与派生，拼接64字符十六进制散列，password_hash 共96字符；校验用恒时比较。

登录成功清空失败计数，创建43字符 sid 会话，并记录登录审计。JWT 使用 HS256，载荷为 user_id、role、sid、iat、exp，exp=iat+1800。每次受保护请求校验签名、令牌期限、会话和 last_activity_at，再读取数据库当前账号状态与角色；权限不依赖旧 JWT 中的角色。验证通过更新最近活动，通常在响应头 X-SmartLab-Token 返回新令牌，客户端接收后替换；退出和改密会清除续签响应，因为这些操作撤销会话。当前不设8小时绝对上限，也没有单独刷新令牌接口。

退出仅删除当前 sid；修改密码或恢复码重置密码会撤销该用户全部会话。账号禁用会使受保护请求被拒绝；当前没有对外账号启停接口，完整禁用联动见第9章规划。当前通用鉴权会将所有受保护请求视为活动并滚动续签；消息后台轮询尚未实现，其不延长用户会话的规划要求须随 M05 改造，不能视为当前既有行为。

### 3.6 流程逻辑

AuthPage 获取账号和密码 → UserViewModel 设置 busy 阻止重复提交 → POST /api/auth/login。成功时直接使用响应 data.token 和 data.user 更新内存状态与页面，无需强制再查当前用户；GET /api/users/me 用于主动刷新资料。失败时展示业务提示，锁定时显示 retry_after；凭据与令牌不得写入日志。

ApiClient 以 Authorization: Bearer JWT 发送保护请求，读取 X-SmartLab-Token 保存滚动令牌。退出成功后清理本地会话；改密成功同样回到登录。保护请求返回401或“账号已被禁用”的403时，UserViewModel 清理本地身份。网络失败或8秒超时向用户报告，不自动重试写请求。

## 4 注册与个人中心模块设计说明

### 4.1 注册与个人中心模块

当前 M01 实现师生注册、本人资料维护、改密、恢复码更新和忘记密码重置，覆盖 FR-101-1、FR-101-3、FR-101-4 的账号主流程。AuthPage.qml 对应 F01 认证入口，ProfilePage.qml 对应 F02 个人资料。violation_count、frozen_until、booking_frozen 可展示预约权限状态，违约记录列表和自动判定尚属 M04 规划。管理员初始账号由初始化入口产生，不允许公开注册为管理员。

当前注册、登录、个人中心及管理员角色页复用 UserViewModel、routers/auth.py 和 UserService。GET /api/auth/roles 从 t_dict 返回可注册的 student、teacher；全部角色为 student、teacher、admin。公开注册严格限制前两类。管理员用户查询及角色调整已实现，完整启停、预约联动和审计检索按第9章规划。

### 4.2 性能

个人资料查询目标不超过1秒；注册、资料修改、密码修改或重置目标不超过2秒。user_no 唯一约束防止并发重复注册。本人违约记录分页的1秒目标属于后续规划，当前未开放该接口。

### 4.3 输入项

| 输入项 | 当前格式 | 校验与边界 |
| --- | --- | --- |
| 注册 | user_no、name、role、college、major、phone、password | 账号8～12位字母数字；name≤20，college/major≤60且必填；role限student/teacher；phone为11位手机号。 |
| 新密码 | password 或 new_password | 8～32位，含英文字母、数字，无换行；确认密码仅客户端校验；未知字段拒绝。 |
| 本人资料 | college、major、phone | 仅允许这3个字段，不能修改账号、姓名、角色、状态或冻结。 |
| 主动改密 | current_password、new_password | 验证当前密码，成功后撤销该用户全部会话。 |
| 忘记密码 | user_no、phone、recovery_code、new_password | recovery_code恰24字符；账号/手机号/摘要匹配后消费恢复码。 |
| 恢复码更新 | current_password | 验证当前密码后生成新24位码，覆盖旧 recovery_hash。 |

### 4.4 输出项

| 输出项 | 当前内容 | 客户端处理 |
| --- | --- | --- |
| 注册 | data={user,recovery_code}，成功HTTP200；账号重复409。 | 提示保存本次恢复码并回到登录。 |
| 个人资料 | PublicUser字段含违约次数、冻结截止及booking_frozen；不含违约明细分页。 | 展示本人资料和当前冻结状态。 |
| 改密或重置 | HTTP200成功；当前密码或重置身份不匹配409。 | 清理会话，以新密码重新登录。 |
| 新恢复码 | data={recovery_code}，仅本次响应交付。 | 提示妥善保存，不写日志或普通配置。 |

### 4.5 算法

当前注册先去除账号首尾空格并转小写，按8～12位字母或数字校验，保留数字前导零。姓名1～20字符，学院和专业1～60字符且必填，手机号匹配 ^1[3-9][0-9]{9}$。新密码8～32位、含英文字母与数字且不含换行；未知字段被拒绝。事务内保存账号、96字符带盐散列和审计；重复账号返回409。注册生成24位恢复码，摘要入 recovery_hash，明文仅随本次响应交付。

当前资料更新仅允许 college、major、phone，按认证用户ID定位。主动改密请求为 current_password、new_password，验证当前密码后生成新盐和散列，清空登录锁定并撤销全部会话。更新恢复码需 current_password，新码覆盖旧摘要，旧码立即失效；改密不自动消费恢复码。

当前忘记密码请求为 user_no、phone、recovery_code、new_password。服务端校验启用状态、预留手机号和24位恢复码摘要，失败返回409；成功在同一事务中清空 recovery_hash、保存新密码、清空锁定、撤销全部会话并写审计。因此恢复码只能用于一次重置。管理员签发短时凭证与 t_password_reset 仅为预留方案，未开放签发接口，也没有用它替代当前恢复码。

### 4.6 流程逻辑

填写师生注册资料 → 校验与事务保存 → 响应 user 和 recovery_code → 客户端提示保存恢复码并回到登录。注册不自动登录，不返回 token，也不产生管理员权限；确认密码仅作客户端一致性校验，不是服务端请求字段。

进入个人中心 → 查询或展示本人资料 → 保存 college、major、phone。改密验证当前密码，成功后重新登录；更新恢复码显示本次新码并提示妥善保存。忘记密码时提交账号、手机号、恢复码和新密码，成功后原码失效，需登录后再生成新恢复码。

| 违约与设备处置 | 未签到或逾期未还记录、冻结截止、设备暂停标记、确认归还记录。 | F06、F09 与 M05。 |

### 7.5 算法

规划审批仅允许 pending → approved 或 rejected，以旧状态检查或行锁防止并发重复。每预约最多一条最终审批记录：approver_id、decision（approve/reject）、opinion、decided_at；驳回必须有意见并同事务释放槽。批准前复核交接状态。待审超2工作日提醒，实验室周开放时段已在 SQL 定义，节假日/工作日日历配置需后续业务实现。

规划签到仅允许 approved → in_use，保存 checked_in_at，并建立每设备至多一条的 t_equipment_custody；尚未交回的设备不得再次交接。正常归还仅允许 in_use → completed，同时填写 returned_at、returned_by、return_note，清除实物占用并释放计划槽。重复操作返回原结果或409，不重复建记录；请求备注 condition_note 映射 return_note。

超过开始后15分钟仍未签到时判违约并释放时间槽。超过结束后30分钟仍未归还时判违约、释放原计划占用槽、记录独立的实物逾期停约并通知用户和管理员。停约标记与计划槽分开维护，新申请返回409，已存在的后续预约保留，由管理员协调、取消或通知，设备交回前不得交接。确认归还后清除停约标记，预约保持已违约，违约记录继续保留。

规划以 (reservation_id,violation_type) 去重；违约类型 no_show/late_return，处理状态 open/resolved，归还确认与解冻分别留痕。累计达到3次冻结未来30天申请资格；到期或解冻恢复但不删历史，重跑不能重复计数或延长冻结。用户冻结是 Unix 秒字段，业务 occurred_at/resolved_at 为 UTC DATETIME(3)，边界转换必须一致。

### 9.5 算法

新建或修改时统一校验台账编号、实验室和类别。设备存在有效预约或待确认交接时不得删除。关联历史记录的设备采用归档式移除，保留原记录引用。停用实验室前处理受其影响的设备和预约。

当前角色调整仅允许管理员操作其他账号，禁止修改自己的角色，按数据库当前角色即时鉴权并记录审计。完整账号禁用属于规划：撤销会话，将待审/批准预约取消并释放槽；已领设备的预约取消后仍保留 admin_pending 实物占用，管理员确认归还前不得重新交接。师生升为管理员前先处置未完成预约，是 M03/M04 接入后的联动规则，当前不能宣称已执行。

规划导入先完整校验全部行，通过后批量写入，任一行冲突整批回滚。台账和账号变更按事务结果追加审计。现有审计字段为 actor_id、target_user_id、action、result、created_at；后续扩展对象、脱敏明细与IP，不存密码、令牌、恢复码或完整凭证。账号启停还须保护最后一个可用管理员，不能将当前禁止自改角色与未来完整管理员保护混同。

### 9.6 流程逻辑

管理员打开 F09 → 选择实验室、设备、账号或日志 → 读取列表 → 维护。对停用和删除操作进行二次确认 → 服务端复核 → 刷新页面并记录审计。

批量导入先读取模板 → 校验全表 → 有错误时返回行号与原因 → 修正并重试。成功后刷新设备列表。

## 10 统计报表模块设计说明

### 10.1 统计报表模块

本章为 M07 规划，覆盖 FR-701-1～FR-701-3，当前无 StatsService、ChartViewModel 或统计API。F10 拟按日期、实验室、类别、设备展示预约量、使用率、违约率和审批通过率，使用 Qt Charts 图表；CSV由服务端导出，PNG由客户端导出。实现时需增加相应 Qt 组件并与构建配置同步。

StatsService 通过只读统计查询从预约、审批、违约和设备开放时段获取数据。按《需求说明书》的指标定义核算，管理员方可访问。

### 10.2 性能

单维度查询目标不超过2秒，多维汇总不超过5秒，页面在2秒内显示加载状态。按5万条预约记录测试，CSV 导出目标不超过2秒且每次最多1万行。

### 10.3 输入项

| 输入项 | 来源或格式 | 约束及校验 |
| --- | --- | --- |
| start_date、end_date | 管理员，日期区间 | 起始不晚于结束，最大180天。按实验室时区转换为左闭右开统计区间。 |
| group_by | day、week、month | 粒度与图表横轴一致，周界按约定的周一划分。 |
| lab_id、category、equipment_id | 可选的资源过滤条件 | 设备与实验室、类别组合必须有意义，空值为全部。 |
| export | 当前筛选条件和图表 | CSV 与图表引用相同快照或统计时间，PNG 由客户端导出。 |

### 10.4 输出项

| 输出项 | 内容 | 使用方 |
| --- | --- | --- |
| 汇总数据 | 统计维度、分组区间、计数、分子、分母、比率。 | F10 概览和图表。 |
| 空数据 | 分母为0返回 null，客户端显示暂无数据。 | F10 避免误以为比率为0。 |
| 导出 | CSV含筛选、列名、分子分母、数值，UTF-8 BOM；PNG含标题、单位和时段。 | 管理员本地保存。 |

### 10.5 算法

规划统计口径：预约量按统计期内申请时间归集，说明有效范围并去重；审批通过率＝批准申请数÷申请总数，分母包含统计期内待审批申请。此处采用新版总体设计口径，不采用“批准÷（批准＋拒绝）”。待审后续状态变化可能影响历史汇总，导出应保留统计快照时刻与筛选条件。

规划违约率＝违约记录数÷已批准预约数，分子分母按同一批申请、资源和时间条件归集；已批准口径须包括批准后进入使用、完成或违约的同批申请，不能仅筛当前 approved 状态。设备使用率＝统计期实际使用时长÷可预约时长；签到/确认归还与统计区间求交，未确认归还单列在用提示，设备有效开放时段作为分母。SQL未保存全部管理状态/开放配置历史，实现历史准确统计时需保存相应有效期或快照，不能直接用当前配置重算后声称历史准确。

查询按时间和设备维度聚合。SQLite 与 MySQL 使用等效时间分组表达式，前端负责图表渲染。各比例在后端统一取舍，保留分子和分母用于抽样手工核对。

### 10.6 流程逻辑

选择统计维度和区间 → 校验 → 调用相应统计接口 → 展示加载状态 → 渲染图表及明细。

管理员触发导出 → 使用当前条件生成 CSV 或 PNG → 保存到本地。若无数据，页面清楚显示原因并允许调整筛选。
